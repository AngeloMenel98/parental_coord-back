# Admin management + bond reports

**Objective:** complete the admin API (activate/deactivate users and bonds, edit/delete
children) and add bond reports: a JSON report endpoint and an asynchronous PDF report
generated by the backend, stored in Supabase Storage and recorded in the existing
`report` table.

**Branch:** `ft/admin-bonds-reports` (from `ft/supabase-cloud`)
**Slice size:** measured against `ft/supabase-cloud`, the branch this one actually
starts from. Against `origin/main` the diff is meaningless: the base is already 73
commits ahead of main.
**Delivery:** 3 reviewable commits, ~400 authored lines each, tests in the same commit.
**Test runner:** `pnpm test` (jest), `pnpm test:e2e` (e2e), `pnpm lint`, `pnpm build`.

## Specs

- **S1 — User activation.** `PATCH /admin/users/:id` accepts `{ "isActive": boolean }`
  and returns `{ id, email, systemRole, firstName, lastName, isActive, createdAt }`
  (the same shape `GET /admin/users` returns per item). Unknown id answers 404 with
  `User <id> not found`. Deactivation never deletes rows or cascades.
- **S2 — Bond activation.** `PATCH /admin/bonds/:id` accepts `{ "isActive": boolean }`
  and returns the same per-item shape `GET /admin/bonds` returns. Unknown id answers
  404 with `Bond <id> not found`.
- **S3 — Child editing.** `PATCH /admin/children/:id` accepts
  `{ "firstName"?: string, "lastName"?: string, "dateOfBirth"?: string }`, where
  `dateOfBirth` is an ISO date (`YYYY-MM-DD`) or `null` to clear it. Returns
  `{ id, bondId, firstName, lastName, dateOfBirth, createdAt }`. Unknown id answers 404
  with `Child <id> not found`. `DELETE /admin/children/:id` answers 204 and removes the
  row.
- **S4 — Child date validation.** The admin child create and update DTOs reject a
  `dateOfBirth` that is not an ISO date with 400; an empty string is rejected, only
  `null`/absent clears it.
- **S5 — Admin guard.** Every `/admin/*` route keeps `JwtAuthGuard` + `RolesGuard` with
  `@Roles(SystemRole.ADMIN)`; a non-admin token answers 403 and an anonymous request 401.
- **S6 — Bond report JSON.** `GET /admin/bonds/:bondId/report?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD`
  returns the bond report. Both dates are inclusive: the window is `dateFrom` 00:00
  through `dateTo` 23:59:59.999 server time, implemented as `>= dateFrom` and
  `< dateTo + 1 day`. Activities are selected by their reference date —
  `scheduled_start` when present, `created_at` otherwise — and expenses by
  `expense_date`. `overdue` counts activities whose status is neither `done` nor
  `cancelled` and whose `deadline` is before `generatedAt`. The payload is:
  ```
  {
    bondId, bondTitle, dateFrom, dateTo, generatedAt,
    activities: {
      total, completed, overdue, completionRate,
      byStatus: { <activity status>: number },
      byCriticality: { <criticality>: number }
    },
    expenses: {
      totalAmount, paidAmount, pendingAmount,
      paidAmountPercentage, paidCountPercentage,
      byStatus: { <expense status>: { count, amount } },
      byCategory: [ { categoryId, categoryName, count, amount } ]
    },
    children: [ { id, firstName, lastName, dateOfBirth, ageInYears, activityCount } ],
    members: [ { userId, firstName, lastName, role, assigned, completed, completionPercentage } ]
  }
  ```
  Unknown bond answers 404 with `Bond <bondId> not found`; a missing or malformed date
  answers 400.
- **S7 — Expenses paid percentage (both units).** `paidAmountPercentage` is
  `sum(amount) of expenses with status 'paid' / sum(amount) of expenses not deleted and
  not rejected × 100`, rounded to 2 decimals. `paidCountPercentage` is the count version
  of the same division. When the denominator is zero both are `0`.
- **S8 — Returned amounts.** Every amount in the report is a number rounded to 2
  decimals, and percentages are rounded to 2 decimals. Deleted (`deleted_at IS NOT
  NULL`) and rejected expenses are excluded from `totalAmount` and from both
  percentages, but a rejected expense still appears in `byStatus`.
- **S9 — Report request.** `POST /admin/bonds/:bondId/reports` accepts
  `{ "dateFrom": "YYYY-MM-DD", "dateTo": "YYYY-MM-DD" }`, creates a `report` row with
  status `requested`, `requested_by` = the calling admin, enqueues one PDF job and
  answers 202 with `{ id, status, bondId, dateFrom, dateTo }`.
- **S10 — Report status.** `GET /admin/reports/:id` returns
  `{ id, bondId, status, dateFrom, dateTo, fileUrl, generatedAt, createdAt }` where
  `fileUrl` is a signed download URL when the report is `completed`/`delivered` and
  `null` otherwise. Unknown id answers 404 with `Report <id> not found`.
  `GET /admin/reports?bondId=<uuid>` lists the same items newest first; without
  `bondId` it lists every report.
- **S11 — PDF generation.** The worker renders the same data as S6 into a PDF, uploads
  it through the storage service, and on success sets `status = 'completed'`,
  `fileUrl`, `generatedAt` and `generatedBy` on the row. A failure leaves the row out of
  `completed` and is logged; it never marks the report completed.
- **S12 — Existing behaviour.** Every existing `/admin/*` route and response keeps its
  current shape and status codes.

computed in UTC. Activities are placed in the window by

`left_at` set is not part of the report.
